# Дом: проблема решена

Чат-бот в MAX для общедомовых неисправностей. Слоган: **одна проблема дома — одна общая заявка**.

## Назначение решения

Житель многоквартирного дома, обнаружив общедомовую неисправность (лифт, свет в
подъезде, протечка, шлагбаум), не знает, сообщал ли о ней кто-то из соседей и
что происходит с заявкой. В итоге 10 жителей с одной проблемой — это 10
обращений в УК, а статус «выполнено» никто не проверяет.

Бот объединяет соседей вокруг одной заявки, показывает всем участникам общий
статус и позволяет жителям подтвердить или оспорить, что проблема устранена.
Диспетчер УК работает с одной заявкой вместо потока дублей. Продукт не заменяет
официальные каналы («Госуслуги Дом», ГИС ЖКХ): если УК нарушает сроки, бот
направляет жителя туда с готовым текстом обращения. Концепция, законы и
позиционирование — в [docs/CONCEPT.md](docs/CONCEPT.md).

## Основной пользовательский сценарий

1. **Житель** открывает бота по QR-коду в подъезде — дом и подъезд уже выбраны
   (без QR — геолокация или поиск по справочнику домов).
2. «Сообщить о проблеме» → категория. Если соседи уже сообщили — «🙋 У меня
   тоже» одним нажатием, без описания. Иначе — описание и фото.
3. Соседи подъезда или всего дома получают оповещение и присоединяются одной кнопкой.
4. **Диспетчер УК** видит заявку с числом жителей, берёт в работу, называет
   срок, назначает исполнителя. Участники получают каждое изменение.
5. Исполнитель отмечает «Выполнено» с фото → жители отвечают «Устранена» или
   «Проблема осталась». Итог решает большинство; решающий голос — у
   председателя совета дома. Нет ответов в срок — статус «выполнено УК,
   подтверждение не получено».

## Состав и архитектура

```text
MAX Bot API (Long Polling) ─→ app/bot/  ─→ app/domain.py ─→ app/store.py ─→ PostgreSQL
                               core      маршрутизация, черновики, уведомления, фоновые задачи
                               resident  житель и председатель совета дома
                               staff     диспетчер и исполнитель
                               admin     администратор УК и сервиса
```

| Компонент | Назначение |
|---|---|
| `app/bot/` | сценарии ролей, клавиатуры, очередь уведомлений, напоминания и эскалация |
| `app/domain.py` | сущности, правила объединения заявок и подтверждения, метрики |
| `app/store.py` | хранилище PostgreSQL (SQLite и in-memory — для тестов), автоматические миграции |
| `app/poster.py` | генерация QR-плакатов для подъездов |
| `app/max_client.py` | HTTP-клиент официального Bot API MAX |
| `app/seed.py` | тестовые данные |

Подробно — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**Роли:** житель; председатель совета дома; исполнитель; диспетчер;
администратор УК (справочник домов, сотрудники, QR-плакаты, показатели);
администратор сервиса (подключает УК). Сотрудники подключаются по одноразовым
ссылкам; для проверки есть вход в роль УК по коду `/uk <UK_ACCESS_CODE>`.

**Возможности MAX сверх минимальных:** ссылки `?start=` в QR-плакатах подъездов
(дом и подъезд выбираются автоматически), кнопка запроса геолокации для поиска
ближайшего дома, загрузка изображений (`POST /uploads`) — бот присылает
готовые плакаты A4, редактирование сообщения по нажатию кнопки, меню команд
бота, кнопки `clipboard` («Позвать соседей», текст официального обращения).

## Запуск

Одна команда запускает все локальные компоненты (бот + PostgreSQL):

```bash
cp .env.example .env    # затем впишите MAX_BOT_TOKEN
docker compose up --build -d
```

Windows PowerShell: `Copy-Item .env.example .env`, затем та же команда `docker compose up --build -d`.

Сборка занимает около минуты. Логи: `docker compose logs -f bot` — должна
появиться строка `Бот MAX запущен`. Запуск на сервере для круглосуточной
работы — [docs/DEPLOY.md](docs/DEPLOY.md).

## Переменные окружения

| Переменная | Обязательна | Назначение | По умолчанию |
|---|---|---|---|
| `MAX_BOT_TOKEN` | да | токен бота MAX | — |
| `UK_ACCESS_CODE` | да, для проверки | код входа в роль администратора УК: `/uk <код>` | `demo-uk-code` |
| `SEED_DEMO` | нет | при запуске добавить тестовые данные | `true` |
| `CONFIRMATION_TIMEOUT_MINUTES` | нет | срок подтверждения жителями (48 ч; для демо можно 10 мин) | `2880` |
| `ORG_NAME` | нет | название УК по умолчанию | `Тестовая УК «Демо»` |
| `UK_ADMIN_IDS`, `UK_OPERATOR_IDS` | нет | MAX user_id администраторов и диспетчеров УК через запятую | — |
| `PLATFORM_ADMIN_IDS` | нет | администраторы сервиса (`/org_new`) | — |
| `OFFICIAL_APPEAL_URL` | нет | официальный канал обращений для эскалации | `https://dom.gosuslugi.ru` |
| `DISPLAY_UTC_OFFSET_HOURS` | нет | часовой пояс в сообщениях | `3` |
| `MAX_BOT_LINK` | нет | ссылка на бота; пусто — берётся из `GET /me` | — |
| `DATABASE_URL`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | нет | подключение к PostgreSQL в Docker | см. `.env.example` |
| `MAX_API_BASE_URL`, `MAX_POLLING_TIMEOUT`, `MAX_REQUEST_TIMEOUT` | нет | параметры MAX API | см. `.env.example` |

Свой `user_id` бот покажет по команде `/myid`. Токены и пароли в репозиторий не
попадают: `.env` исключён в `.gitignore` и `.dockerignore`.

## Внешние сервисы и интеграции

| Сервис | Как используется | Условия проверки |
|---|---|---|
| **MAX Bot API** (`platform-api2.max.ru`) | `GET /me`, `PATCH /me/commands`, `GET /updates`, `POST /messages`, `POST /answers`, `POST /uploads` | внешний сервис, в Docker не воспроизводится: нужен токен бота и доступ в интернет |
| ГИС ЖКХ, ФИАС, «Госуслуги Дом» | **интеграции нет**. Справочник домов — тестовые данные; для эскалации бот даёт ссылку `OFFICIAL_APPEAL_URL` и готовый текст обращения | — |

## Работа с данными

- **Что хранится:** id пользователя MAX, выбранные дом и подъезд, согласие на
  обработку, заявки (текст, фото — токены MAX), голоса, журнал событий заявки,
  роли сотрудников, справочник домов, черновики диалогов. Имена и телефоны
  жителей не сохраняются.
- **Где:** PostgreSQL в Docker-томе `postgres_data`.
- **Доступ:** жители видят заявки своего дома без имён соседей; сотрудники —
  только заявки своей УК; справочник и сотрудников меняет только администратор УК.
- **Согласие:** при первом входе житель подтверждает обработку данных одной кнопкой.
- **Метрики** считаются по журналу событий: доля дублей, повторные обращения,
  доля подтверждённых и оспоренных выполнений, время до подтверждённого устранения.

## Тестовые данные

При `SEED_DEMO=true` (по умолчанию) при первом запуске создаются
**синтетические данные** — реальных домов, жителей и УК среди них нет:

- Тестовая УК «Демо» (название из `ORG_NAME`);
- 4 дома с координатами: `ул. Ленина, 10` (id `len10`, 4 подъезда), `ул. Ленина, 12` (`len12`),
  `пр-т Мира, 5` (`mira5`), `ул. Садовая, 3к1` (`sad3`);
- 13 заявок во всех статусах, включая просроченные, оспоренную и подтверждённые,
  с журналом событий — чтобы очередь и показатели были наполнены;
- исполнитель «Сантехник Иван» и объявление УК по дому `ул. Ленина, 10`.

Повторный запуск данные не дублирует. Вручную (с вашими user_id):
`docker compose run --rm bot python -m app.seed --resident-id <id> --admin-id <id> --master-id <id>`.

## Пошаговый сценарий проверки

Понадобятся два аккаунта MAX: **А** — житель, **Б** — сотрудник УК.

| # | Кто | Действие | Ожидаемый результат |
|---|---|---|---|
| 1 | А | Открыть ссылку `https://max.ru/<бот>?start=h_len10_1` (так работает QR-плакат) | Приветствие и кнопка согласия |
| 2 | А | «✅ Согласен, продолжить» | «Ваш дом: ул. Ленина, 10, подъезд 1», главное меню, список открытых проблем дома |
| 3 | Б | Отправить боту `/uk <UK_ACCESS_CODE>` | «Демо-режим: вы администратор УК», в меню «Очередь заявок» и «Управление УК» |
| 4 | А | «➕ Сообщить о проблеме» → «🛗 Лифт» → написать «Лифт застрял на 3 этаже» | «✅ Заявка создана» с номером, статусом, нормативом и приоритетом |
| 5 | Б | — | Сообщение «🆕 Новая заявка» с кнопкой «Взять в работу» |
| 6 | Б | «🛠 Взять в работу» → «Завтра» → «💬 Сообщение жителям» → текст | У А: «УК взяла заявку в работу», «назначила срок», «Сообщение от УК» |
| 7 | Б | «✅ Отметить выполнение» → «Без фото» | У А: «УК сообщает, что проблема устранена» с кнопками ответа |
| 8 | А | «✅ Устранена» | «Жители подтвердили выполнение — заявка закрыта»; у Б — уведомление |
| 9 | Б | «🛠 Управление УК» → «📊 Показатели» | Пять метрик пилота по УК |

Дополнительно:
- **Общая заявка:** третий аккаунт открывает `?start=h_len10_1`, выбирает «🛗 Лифт» → бот показывает заявку А, «🙋 У меня тоже» → в заявке 2 жителя, у Б — уведомление.
- **Массовое оповещение:** житель подъезда 1 сообщает о «🚧 Двор и шлагбаум» → остальные жители дома получают оповещение с кнопкой «У меня тоже».
- **Выбор дома без QR:** `/start` → «📍 Отправить геолокацию» (показывает ближайшие дома) или написать «ленина 10».
- **QR-плакаты:** Б → «Управление УК» → «Дома и QR-коды» → дом → «🖨 QR-плакаты» → картинки A4.
- **Очередь:** Б → «🏢 Очередь заявок» — сверху срочные и просроченные, фильтры и страницы.

## Примеры ожидаемого поведения

- Житель выбирает категорию, по которой в его подъезде (для лифта, света,
  мусоропровода) или доме (для протечки, отопления, двора) за 72 часа уже есть
  открытая заявка, — бот предлагает присоединиться вместо новой заявки.
- «Другое» никогда не объединяется и не рассылается соседям.
- Из 3 участников «Устранена» ответили двое — заявка подтверждена; ответил один
  «Проблема осталась» — диспетчер получает предупреждение, заявка ждёт остальных.
- Ответили все, голоса разделились поровну — заявка возвращается УК («оспорено»).
- Через половину срока молчащим участникам приходит напоминание; по истечении
  срока итог решает большинство ответивших, без ответов — «подтверждение не получено».
- Истёк норматив устранения — диспетчер получает эскалацию один раз, жители —
  кнопку официального обращения с готовым текстом.
- Ввод текста вместо кнопки, устаревшая кнопка, чужая заявка — бот объясняет, что
  сделать, и возвращает меню; перезапуск бота посреди сценария не теряет шаг.

## Известные ограничения

- Интеграции с ГИС ЖКХ, ФИАС и «Госуслуги Дом» нет — справочник домов и
  заявки тестовые; официальное обращение житель подаёт сам по ссылке.
- Сроки устранения по категориям — ориентиры по умолчанию, а не нормативы;
  УК задаёт свои в `CATEGORIES` в `app/domain.py`.
- Житель выбирает дом только из справочника УК; новый дом добавляет администратор УК.
- Закрепление сообщений в MAX работает только в групповых чатах, поэтому в личном
  диалоге используется меню команд бота.
- Кнопки геолокации и копирования зависят от клиента MAX; если геолокация
  недоступна, дом выбирается поиском.
- Чат дома (`/link КОД`) — опция: бот должен быть добавлен в чат его администратором.
- Решение — чат-бот без мини-приложения: сценарий целиком проходит в диалоге с ботом.

## Остановка и повторный запуск

```bash
docker compose stop            # остановить, данные сохраняются
docker compose up -d           # запустить снова
docker compose up --build -d   # пересобрать после изменения кода
docker compose down            # удалить контейнеры, данные в томе сохраняются
docker compose down -v         # удалить и данные PostgreSQL (необратимо)
```
